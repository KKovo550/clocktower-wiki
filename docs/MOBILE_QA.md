## iPhone 13 Pro Max：Safari 操作步骤

用 Safari 打开 [线上剧本工具](https://kkovo550.github.io/clocktower-wiki/script_tool/%E5%89%A7%E6%9C%AC%E5%B7%A5%E5%85%B7.html)。先导出正在使用的剧本，再新建一份测试草稿，不对已有正式剧本执行清空。

1. 载入一个官方预设，把名称改为「手机验收」，作者填任意测试名字。收起键盘，检查名称、作者、已选人数以及页面底部操作栏均能使用。
2. 点击「导出 JSON」。在 Safari 的下载记录或「文件」App 找到 `.json` 文件。返回页面，通过「导入 JSON」选择刚保存的文件，确认预览的名称、作者和角色数一致，再确认导入。
3. 打开「生成剧本图片」，等待预览完成，使用「保存 / 分享图片」。长按图片保存，再从相册查看完整图片；另外测试系统分享是否可打开。相册和分享是 iOS 系统行为，桌面引擎无法替代。
4. 竖屏和横屏各检查一次「我的剧本」：顶部标题和操作按钮不盖住角色，末尾角色可滚到，更多操作可展开。编辑较长的剧本名称，检查系统键盘弹出后输入框仍可见、收起后底部按钮恢复。
5. 修改名称后立即切到其他 App，锁屏一段时间再返回，确认内容仍在；再刷新一次，确认内容一致。手机后台结束进程时离开提示不一定有机会触发，因此这里必须检查实际恢复结果。
6. 在同一 Safari 的两个标签中打开同一草稿。A 修改作者，B 修改名称。B 应显示「另一页面已更新草稿」，先导出 B 的 JSON，再刷新 B；A 保存的内容不能被 B 覆盖。
7. 在测试草稿中使用「更多操作 → 清空」，确认清空生效，再用撤销或草稿恢复点确认可以找回刚才的测试内容。
8. 打开 [剧本库](https://kkovo550.github.io/clocktower-wiki/script_lib/%E5%89%A7%E6%9C%AC%E5%BA%93.html)，打开一张图片，检查关闭、缩放、拖动、图片保存和横竖屏切换。断网后打开一张尚未缓存的图片，再联网点重试，确认恢复；已缓存图片仍能显示属于正常现象。

不需要清理 Safari 网站数据或关闭所有现有标签。无痕模式应单独测试，不能用它判断普通模式的数据持久性；不同设备和浏览器间不会自动同步草稿。

反馈时记录：手机型号、iOS 版本（设置 → 通用 → 关于本机）、Safari/普通或无痕、页面链接、操作步骤、预期与实际结果。导出失败时注明「没出现下载」「文件打不开」还是「文件内容不对」。

## 多人持续试用

建议由 3–5 位参与者分别在自己的浏览器使用至少一周，覆盖编辑、导入导出、看图和说书夜序；这是待执行的试用安排，不代表已有一周观察记录。测试参与者自行使用和反馈，不自动收集或上传剧本、玩家名字与现场备注。

每次使用结束导出测试 JSON，次日打开检查名称、作者、角色数和夜序备注。记录连续使用天数、设备/浏览器、遇到的问题、是否可重现、是否有导出备份。发现数据丢失、其他标签的内容被覆盖、JSON 无法回导或关键按钮无法使用时，暂停将该设备标记为通过，保留导出文件和操作记录，再修复并重测。

静态站点的不同用户各自使用本地存储。下面的隔离测试验证浏览器间不会串存档，不是服务端负载压测，也不证明多人实时协作或跨设备同步。

## 可重复的自动回归

以下命令需要完整的本地源码项目；公开 GitHub 仓库仅包含网站发布产物，不能只克隆公开仓库后运行源码测试。安装可选测试依赖到本地忽略目录，不修改网站生产依赖。在 PowerShell 的项目根目录执行：

```powershell
npm install --prefix .sync/mobile-qa/runtime --cache .sync/npm-cache --no-audit --no-fund playwright@1.64.1
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.sync/mobile-qa/browsers"
node .sync/mobile-qa/runtime/node_modules/playwright/cli.js install webkit
node scripts/test-mobile-compat-browser.cjs
```

Chrome 使用已安装的 Chrome；WebKit 使用本地下载的测试浏览器。两者都创建隔离上下文，不读取个人浏览器资料。浏览器进程需要在允许启动测试浏览器的环境运行。

默认测试 `dist/astro`，因此先有经过验证的构建。每种引擎覆盖 6 个页面的横竖屏布局、实际触屏操作、JSON 文件下载并解析、1111 × 1500 PNG 保存预览、30 轮自动保存及定期完整重载、8 轮共享存储的标签冲突与未保存内容导出、4 个独立用户共 40 次修改并重载、关闭编辑页面后重新打开恢复。

`MOBILE_QA_ROUNDS` 可设 1–300；上限用来避免误配置无限循环，不把快速循环称为长期真机测试。更多轮数只增加自动保存循环；冲突测试最多 8 轮，每位独立用户最多 10 轮。

线上验收可指定地址与独立报告目录：

```powershell
$env:MOBILE_QA_BASE = 'https://kkovo550.github.io/clocktower-wiki'
$env:MOBILE_QA_ROUNDS = '3'
$env:MOBILE_QA_OUTPUT = '.sync/mobile-qa/live'
node scripts/test-mobile-compat-browser.cjs
```

其他参数：`MOBILE_QA_ROOT` 指定静态构建目录；`MOBILE_QA_PLAYWRIGHT` 指向已安装的 Playwright 模块目录。默认报告在 `.sync/mobile-qa/results/results.json`，记录实际版本、引擎版本、页面尺寸、轮数和失败信息；PNG 保存预览截图也在同一目录。即使失败也写报告，不得根据单张截图判断整个流程通过。`.sync` 不发布。
