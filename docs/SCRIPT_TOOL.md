# 剧本工具：数据与状态约定

### 角色目录与导入

基础角色目录维护于 `config/script-tool/roles.json`，基础相克与预设在同目录 JSON 文件中；`script_tool/assets/script-tool/data.js` 是构建产物。构建合并海外自制角色，再生成夜序与奥德赛相克数据；生成区块不要手动维护第二份。

角色库支持官方、群星、海外自制、奥德赛四个来源筛选，与角色类型和关键词取交集。来源使用目录中明确的 `source` 字段（`official`、`stars`、`yuque`、`odyssey`），不按角色名或版本数字推断；未知自定义角色只出现在“全部来源”。按钮计数考虑其他筛选条件，零结果仍保留按钮，筛选不改变已选剧本。回归检查为 `node scripts/test-source-filter.cjs`。

`core.js` 负责导入、草稿校验、夜序和相克匹配，`app.js` 负责主界面状态，`checks.js` 展示搭配检查。角色 ID 必须唯一，名称相同不代表同一角色。ID 匹配兼容首尾空格与标准 `_gstone` 后缀，但保留原始 ID。

导入先完整校验，再替换当前剧本；失败不部分导入，取消保留导入窗口和文本。支持 BOM、明确的数字文本夜序和图片 URL 数组。仅有未知 ID、重复 ID 或无效字段会报错；非标准扩展元数据不会完整保留。

### 夜晚行动顺序

`pages/夜晚行动顺序一览.html` 是默认夜序来源。`integrate_odyssey_nights.py` 根据奥德赛页面的前位角色合并行动，`integrate_editor_nights.py` 生成 `SCRIPT_NIGHT_ORDER`。

`ScriptCore.nightOrder` 统一计算最终顺序，手动调整保存在草稿中，导出时写入 `firstNight` 和 `otherNight`。已匹配角色在某夜不行动时为 0；明确待定位或表外角色保留导入值，不猜测顺序。列表显示的序号不等同于 JSON 中的夜序数值。

### 相克规则

`integrate_odyssey_jinx.py` 从奥德赛总表及角色说明提取规则，同时更新编辑器与百科“相克规则”页面。`ScriptCore.matchJinx` 供相克提示、搭配检查和制图共用：按 ID 优先匹配，无 ID 时按名称匹配；有歧义不自动选定角色，重复规则去重。

自定义相克可在制图界面选择两个角色并填写说明，支持修改、删除和浏览器保存。它只影响当前角色组合的图片，不修改全站相克数据，也不写入剧本 JSON。

### 自制角色与个人角色库

“自定义角色”工作台支持编辑、复制、图标上传及预览，可直接加入当前剧本，再进入该角色的规则或夜序编辑。未保存的表单独立暂存；保存失败不会覆盖剧本。编辑已有角色保留 ID、规则和手动夜序，复制角色使用新的 ID。

保存后的自制角色自动收录到“个人角色库”，跨剧本复用时加入独立副本。个人库更新不会自动更改各剧本：先查看版本差异，再勾选要更新的草稿。界面显示当前剧本是否已加入、资料是否一致以及每份剧本的变化字段；内容一致的草稿无需更新。“选择全部待更新”只选择有变化的草稿，切换版本或刷新角色库会清空选择。更新为一次完整保存，每份受影响的剧本先保留恢复点，原规则、夜序和未勾选的剧本保留。另一页面已经完成相同更新时不重复创建恢复点。

个人库最多收录 200 个角色，每个角色保留最近 20 个版本；恢复旧版本创建新的最新版，各剧本仍需主动更新。“收录本剧本版本”可将当前剧本的独立修改保存到个人库，也可重试此前的收录失败。“收录已有草稿角色”仅导入尚未收录的 ID；备份导入同样不覆盖已有 ID。角色和版本保存在当前浏览器的 IndexedDB，不是 GitHub 或云端同步；请用“导出角色库备份”保留跨设备可导入的完整副本。直接文件页面与网站属于不同存储来源，迁移时也需导出／导入备份。

实现：`personal-role-store.js` 管理定义、历史和存储，`personal-roles.js` 管理角色库交互，`custom-roles.js` 管理角色工作台。回归检查：`scripts/tests/personal-roles.test.cjs`、`scripts/tests/custom-roles.test.cjs`；实际浏览器检查：`scripts/test-custom-role-browser.cjs`。

### 草稿保存与海报

主编辑器的“撤销 / 重做”涵盖角色增删与排序、自制角色资料、剧本规则、手动夜序及名称作者。连续输入名称和作者合并为一次修改；保留最近 50 步，并按约 16 MiB 控制历史体积。清空、导入和预设替换可撤销；主动打开另一份草稿或恢复草稿版本后重新开始历史。撤销只作用于当前编辑器，不回退个人角色库版本或其他草稿的批量更新。Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y 在主界面操作剧本，输入框仍使用浏览器原生文字撤销，制图窗口保留自己的撤销历史。撤销先检查草稿存储冲突，失败时保留当前内容；刷新后保留最终草稿，操作历史不跨刷新保存。

“完整备份”下载 `kind: clocktower-workspace` / `version: 1` 的 JSON，包含全部草稿及恢复点、当前剧本、个人角色库及版本、制图存档、个人方案和其中的 Logo / 背景，以及制图查看偏好和暂存角色表单。最多 100 MB；仅收集剧本工具明确管理的数据，不包含网站登录凭据或其他网页存储。恢复前完整校验并显示备份、本地的内容数量；恢复会替换上述资料，先自动下载恢复前备份，成功后刷新载入。各数据库独立事务，发生中途失败时按相反顺序尝试回退，并明确报告无法还原的部分；预览后本地发生变化或其他页面修改资料时拒绝覆盖。可在网站和本地文件页面之间迁移，不需要登录云端账户。

制图预览支持直接拖动 Logo、剧本作者和特殊规则框，并用右下角手柄调整 Logo 的等比大小、规则框的宽高。作者只移动，不改变字号；点击作者可编辑姓名，“剧本信息 → 作者位置调整”提供水平／垂直偏移和恢复原位。作者文字限制在页眉及画布左右安全区内，不自动移动其他元素，调整时请避开 Logo、人数和规则框。位置随撤销、制图存档、个人方案和工作区备份保存，旧存档默认原位。作者拖动与滑块使用缓存 SVG，只变换作者图层，不逐帧重算正文；松手后的正式 SVG 与快速预览使用同一几何计算。上下位置也可在对应调整栏输入；拖动写入同一组参数，边界限制和换行仍由现有 SVG 渲染器处理。接近原位置时吸附并显示辅助线；方向键微调，Shift 加大步长。一次拖动为一次制图撤销；Escape、指针取消、窗口失焦或关闭制图会恢复拖动前参数。辅助线和手柄仅在界面中显示，不进入 PNG / SVG。正文、阵营分区、夜序与画布尺寸不随拖动改变。

Logo 连续调整使用缓存的 SVG 预览，只更新标题图层变换，不在每帧重算正文、生成整张 SVG 或重复解析图片。画布拖动松手、滑块释放或数值输入结束后统一生成正式预览和导出数据；调整期间暂停导出，避免保存旧位置。边界与作者避让由 `ScriptArt.titleAdjustment` 统一计算，快速预览与正式 SVG 共用；已有自定义规则框需要避让时，只更新规则框自身的几何和换行。临时预览在图片完成解码、关闭窗口或发生错误时清理。可运行 `node scripts/test-art-logo-performance.cjs` 在真实 Chrome 中复测信口雌黄连续拖动的重算次数和耗时；结果写入忽略版本控制的 `.sync/logo-performance-20261015/`。

草稿保存在当前浏览器中，不是云端同步。恢复时先完成全部校验和迁移，再应用状态；损坏草稿保留原始存储，并阻止自动覆盖。重要剧本应及时导出 JSON，清理浏览器或切换设备可能丢失草稿。

“戏子（改）”使用独立 ID `xizi_revised_gstone`，“戏子”使用 `xizi_gstone`。包含名称的旧草稿可自动迁移改版及其夜序；只有旧共享 ID 的 JSON 无法辨认改版，需重新选择。

`art-core.js` 负责布局和 SVG，`art.js` 负责交互与导出，`art.css` 负责制图界面。图片中的说明和排序独立于主剧本；夜序始终读取主剧本设置，撤销图片操作不回滚外部夜序。重新打开制图时同步主界面已更改的标题与作者。

本地草稿由 `drafts.js` 管理持久化、`draft-ui.js` 提供“我的草稿”界面，仍通过 `ScriptCore.restoreDraft` 验证原有版本 2 数据。`botc_script_drafts_v1` 保存最多 50 份草稿，每份最多 5 个恢复点；`botc_script_tool_v1` 保留当前剧本的兼容副本。旧存档首次打开会迁移，损坏数据不覆盖。保存先写草稿库再写兼容副本，重新载入优先恢复草稿库中的当前内容；另一页面修改草稿库时拒绝继续覆盖并提示先导出备份。切换草稿会隔离图片中的能力与相克编辑，制图设置继续沿用现有行为。首页仅读取 `botc_script_resume_v1` 的名称和角色数提示，不载入完整角色库。

JSON 导入先解析并显示预览，确认后才调用原有 `doImport`。修改输入会使确认失效；换文件、关闭窗口和过期的读取回调不会覆盖新输入。主编辑器的 JSON、OCR、剧本库导入仍共用原有解析与替换入口。

制图调整栏按用途折叠分组：剧本信息、常用版式、角色与夜序调整、正文排版、标题与 Logo、背景、夜序边栏与页脚、规则。支持设置搜索、全部展开／收起和快捷跳转；清空搜索会恢复此前的展开状态与滚动位置。桌面端撤销、重做、保存和生成状态固定在栏底，参数区与图片预览分别滚动。栏宽可拖动调整，也可从“栏宽”菜单加宽或恢复，浏览器记住宽度；手机保留设置／预览切换与固定保存按钮。搜索、折叠和调整栏宽不会修改制图参数或重新排版；从画布或错误提示跳到对应字段时自动清空搜索、展开所需设置，并避开手机顶部搜索栏。

“我的制图方案”保存外观参数、背景和上传的 Logo，可跨剧本套用，不替换角色、标题或规则。最多保存 12 个方案，同名更新；套用支持撤销。当前剧本的制图能力、排序、规则、参数和上传图片另行自动保存，刷新后仅在源剧本内容与元信息一致时恢复，保留最近 8 份存档。`art-settings.js` 优先使用 IndexedDB，自动保存只写当前记录并按索引清理旧存档，不读取其他存档的图片；不支持时回退到浏览器存储，失败会提示。存档不包含夜序，仍以主剧本为准。背景、底纹、装饰、夜序边栏和术语框支持缩略图选择，并与原下拉同步。修改项相对当前预设或本次初始值标记，各组“恢复本组”支持撤销，不影响其他组；角色与夜序组沿用原有排序恢复入口。

预览区支持“设为对比基准”和“按住对比”：基准保存当前 SVG，鼠标、触屏或空格／回车按住时显示基准，松开、取消或离开窗口后返回当前效果。对比期间关闭角色与夜序点击区域，导出仍使用当前 SVG；对比不修改制图数据、正文布局、历史记录或存档。更新基准会释放旧图片地址，关闭制图窗口会清除基准。`botc_art_view_v1` 单独记住分组和素材选择器的展开状态、预览缩放，以及最近 8 个剧本各自的调整栏和预览滚动位置；关闭重开和刷新后恢复。手机分别记住设置与预览的位置，隐藏预览的位置在显示后恢复；窗口宽度改变时按图片显示宽度调整位置。临时搜索和对比不会覆盖原来的查看记忆。

参考海报版式支持纸色、暗纹朱红、靛蓝紫色及真实纹理夜序边栏，以及十二种标题 Logo 风格和自定义 Logo 图片。没有特殊规则时标题居中；填写特殊规则后标题与规则分区显示。版本号、适用人数和副标题可独立填写，设置支持撤销、重做和本次制图重新打开。单个传奇或奇遇角色在底部居中。

“标题与 Logo → Logo 位置与大小”提供水平偏移（画布宽度的 -40% 到 40%）及等比大小（25% 到 160%），支持滑块、直接输入和只恢复 Logo 调整。0 / 100% 对应原有位置和大小，未调整时保留原有 SVG；文字预设、上传图片及 AI 生成图片共用这两个参数。正文、作者、装饰、规则框和画布尺寸不随调整变化。实际显示按标题区边界限制，界面显示实际比例和偏移；有作者及规则框时进一步避让。参数随撤销、制图存档和个人方案保存，旧方案缺少这两个参数时使用原值。切换快速版式恢复 0 / 100%。预览和 PNG、SVG 导出共用同一变换。

“相克与特殊规则 → 特殊规则框调整”提供水平偏移（-40% 到 40%）、框宽和框高（60% 到 160%）及规则字号（16 到 28），支持滑块、数值输入、单独复位、撤销和本地存档。规则为空时禁用，导入的全局作者规则也可调整；正文和 Logo 的位置不受规则框调整影响。框宽变化后按实际文字测量重新换行，保留手动换段及空行，避开行首闭合标点和行尾开括号，尽量保留英文、数值单位和常用中文词，减少末行仅 1–2 个字的情况。规则框保持在原有正文预留区内，并避让标题；不足时先适配规则字号，再在预留区内扩高，仍放不下时明确提示调整框宽或恢复设置，不截断原文。界面显示实际偏移、框尺寸百分比和字号；预览点击区域读取最终框位置，PNG 与 SVG 共用相同结果。

默认固定模式的 PNG 原始清晰度与 SVG 均为 1111 × 1500；PNG 2 倍为 2222 × 3000，SVG 原尺寸不变。显式选择的自动加长模式仍保留旧导出限制。制图优先使用本地图标：直接路径、角色 ID、名称与类型依次匹配；同名有歧义时进一步核对能力，不自动猜选。匹配只补图标，不改动导入角色的能力、ID 或夜序。

未收录角色也支持图片：首先按原始图片 URL 查找本地缓存，再尝试远程加载。原图不允许跨域读取时，通过本站 Worker 的 `/api/role-icon` 获取位图并内嵌为 PNG；图片数组仍可回退到备用地址。成功读取的结果在当前页面缓存。已失效、没有图片字段或来源不受支持时才使用文字占位；只包含未知 ID 的 JSON 仍需提供完整角色对象。内置图标可离线使用，未缓存远程图片需要联网。

「三教九流 4.5.1」的 36 个外部角色图标已按 URL 固定为本地素材，不增加百科角色收录，也不替换导入能力、ID、夜序或 JSON 图片字段。维护清单为 `config/script-tool/icon-images.json`，图片输入位于 `config/script-tool/imported-icons/`；`build_art_icons.py` 校验 SHA-256 后将其内嵌到 `art-icons.js`。正常构建不联网下载图标。新增缓存可显式运行 `scripts/cache_imported_icons.py <剧本JSON路径>`，当前下载命令仅接受已核查的 Gstone 角色图标来源。

默认“复古官方风 · 固定参考图尺寸”锁定 1111 × 1500，在画布内调整正文空白、间距及密度；内容仍无法容纳时提示并停止导出，不自动增高或裁切能力。正文名称显示为实心粗宋体并沿用原 SimHei 测量，能力正文使用 Sarasa UI SC。没有术语说明时释放底部预留高度，增加角色间距；恶魔及较短列按剩余空间适度展开，仍保留底部夜序说明的安全空间。需要保留字号并增加高度时，主动选择“允许自动加长”或对应旧预设。

### 独立夜序查看器

从网站“工具 → 剧本夜序查看器”或剧本工具的“导入 JSON 查看夜序”进入。支持文件、粘贴以及只读载入剧本工具当前草稿；载入草稿保留手动夜序。默认保留 JSON 明确给出的夜序（包括 0），缺省值使用本站数据；可切换为本站夜序表。仅列当前剧本角色，不添加通用夜间阶段。默认使用“现场执行”，也可切换首夜与其他夜晚对照。角色卡片显示图标、已有百科入口、本夜提示及折叠能力；缺提示时明确标注能力作为参考，不当作操作说明。已知有提示但缺少位置的角色单独列入“行动位置待核对”，不推测排序。

可登记及修改玩家名字、角色、座位顺序、生死状态、醉酒/中毒标记和备注。勾选“只显示在场角色”过滤列表与复制内容；同角色多人合并显示，名单为空时结果为空。生死和异常标记只作记录，不自动排除角色行动。第 1 夜使用首夜表，第 2–99 夜使用其他夜晚表，完成、跳过与撤回按夜独立保存；添加、移除或更换玩家角色重置受影响角色的当前夜进度，其他夜晚保留。完成及跳过卡片折叠提示，仍可展开回看。

独立对局自动保存于 `botc_night_session_v1`，刷新恢复当前夜、名单、备注及进度，不写入或清除编辑器草稿。存储失败和其他页面写入冲突均明确提示，可继续执行并下载完整对局备份。备份 `kind: "clocktower-night-session"` / `version: 1` 可从同一文件入口恢复；格式、角色引用、玩家记录及夜间进度先完整校验。导入失败保留对局与存档；成功导入新剧本建立新对局。剧本 JSON 上限 2 MB、对局备份上限 8 MB、最多 100 位玩家。备份按 UTF-8 字节校验并紧凑保存，允许额外的玩家记录和跨夜进度。剪贴板不可用时提供选中的文本供手动复制。现场执行复制当前夜，对照模式复制两夜；待定位提示随文本保留。

实现：`night-session.js` 管理独立状态与校验，`night-viewer.js` 管理导入和展示，`night-viewer.css` 限定查看器样式。测试：`scripts/test-night-viewer.cjs`、`scripts/tests/night-session.test.cjs`，后者已接入 `npm test`。
## 统一角色图床

已收录角色的公开图标由 `scripts/build_hosted_icons.py` 从本地图标生成，目标站点配置在 `config/icon-host.json`。生成的 PNG 与清单位于 `script_tool/hosted-icons/`，导出地址映射随 `data.js` 生成。剧本工具导出 JSON 时，已匹配的收录角色优先使用统一 HTTPS 地址；未匹配的自定义角色保留原有图片字段。

文件名使用 PNG 内容的 SHA-256；同图复用、更新换新地址。发布时须保留已上线的旧图标文件，避免历史 JSON 地址失效。新图标与导出代码应在同一次发布中上线；本地生成并不代表地址已可访问。GitHub Pages 图片仍需要用户网络能访问 GitHub Pages。

本地图标与内嵌制图资源继续保留，制图不依赖远程图床。外部导入文件的原始图片地址保留在内存中；导出已收录角色时以统一图床为准。
### 从图片导入剧本

默认使用 **PaddleOCR 浏览器识别（无需服务）**：在现有图片导入窗口选择图片并开始识别，无需启动 Python、CMD 或本地服务器。直接打开 HTML 与正常网站均支持；图片在浏览器中处理，ONNX 模型和 WASM 通过本地脚本载入，离线包无需网络。首次初始化需要加载约 70 MB 的运行资源，速度取决于设备；识别后需核对同名角色和遗漏角色。原版 Tesseract 离线引擎可在选择框中切换。

浏览器实现：`@paddleocr/paddleocr-js` 0.4.2，PP-OCRv5 mobile 检测与识别模型，ONNX Runtime WebGPU / WASM 单线程。默认保持 CPU 兼容模式；可选择“PaddleOCR GPU 加速（试验）”，优先尝试 GPU，不支持或模型初始化失败时自动回退 CPU，GPU 在独立 Worker 中运行；初始化或推理超过 45 秒时终止 Worker 并回退 CPU，换图或关闭窗口也会取消 GPU 任务。完成提示会显示实际使用的模式。GPU 首次编译着色器可能较慢，不保证每台设备都提速。GPU 与 CPU 分别缓存模型和同一文件的识别结果；标题按原图片缓存，切换排版不会重复识别标题。双列海报根据文字坐标排除两侧夜序，保留原图识别以避免裁切影响准确率。CPU 与 GPU 共用按需加载的 Worker 引擎（约 11 MB），页面端控制脚本约 4 KB，不再重复打包识别引擎。模型及运行资源并行加载。CPU 推理超过 120 秒会终止并提示重试；取消或换图会终止对应 Worker。WebGPU 运行文件使用当前 ONNX Runtime 对应的 asyncify 版本，必须与运行库同步升级。`scripts/prepare-paddle-browser.mjs` 生成浏览器引擎及模型脚本；初次取模型可运行 `scripts/download-paddle-browser.mjs`，有已生成离线模型脚本时构建无需重新下载。SDK 的 HTTP 来源限制在构建时仅对本适配器放开，因为模型通过同上下文 Blob URL 提供，不读取 `file://` 模型地址。升级 SDK 时必须重新验证断网、直接打开 HTML 的识别流程。

保留的 Python 后端用于开发对比：安装 Python 3.12，在独立环境中执行 `python -m venv .venv-ocr`，然后 `.venv-ocr/Scripts/python.exe -m pip install -r requirements-ocr.txt`。`scripts/paddle_ocr.py` 可运行 PP-OCRv5 server 模型。其本机接口不再出现在图片导入窗口，正常使用无需启动。

Python 对比环境可设置 `SCRIPT_OCR_PYTHON` 指向对应解释器；Windows 验证使用 PaddleOCR 3.5.0 / PaddlePaddle 3.3.1。浏览器引擎完全不依赖此环境。

点击“导入剧本图片”，选择 PNG、JPEG 或 WebP，使用双列海报或整图识别。默认图片在浏览器本地通过 PaddleOCR 识别，可切换 Tesseract.js 6.0.1；引擎、Worker、WASM 和中英文模型均放在本站 `assets/script-tool/ocr/`，首次从本站加载，图片不会发送给识别服务。双列模式按文字坐标忽略左右各约 7% 的夜序栏及顶部约 9% 的标题区；角色紧贴图片顶部时应选择整图识别。

角色名仅匹配行首（允许数字序号），避免标题后缀误匹配短角色名。识别后务必校对名单：可取消误识别角色、补选遗漏角色，或修改识别文字重新匹配（每行一个角色名）。同名角色须手动核对。填写名称、作者并确认导入后，使用现有“导出 JSON”按钮；能力、图标和默认夜序来自当前角色库，图片中的特殊能力修改、相克规则及自定义夜序不会自动恢复。图片上未收录的角色可导入后通过自定义角色编辑器补充。

识别组件按需加载，取消对话框会释放识别任务。最大文件 20 MB、最大图片 3200 万像素。识别失败时仍可手动粘贴名单或补选角色。

图片资源保护：上传 Logo 最多 1600 万像素，背景及相册图片最多 3200 万像素。PNG/JPEG/WebP 会先读取最多 256 KB 的文件头检查尺寸，再进行浏览器解码；未能从文件头取得尺寸的格式仍在解码后检查。图片读取、转换与 PNG 导出的解码和编码阶段各有 30 秒超时；超时可重试或改为 SVG。PNG 导出同一时间只运行一个任务，修改预览或关闭制图窗口会取消旧导出，关闭窗口也取消待处理的上传和远程图标。临时 Canvas、ImageBitmap 与 Blob URL 在成功、失败及取消时释放。PNG 栅格化最多 1600 万像素、单边 8192；复古普通内容保留 1111 × 1500，多角色在智能适配模式按需加长；严格固定模式超限会提示，不能默默裁掉正文。

撤销历史最多 30 步，图片数据通过共享引用保留，避免每次修改都复制 Logo 和背景；历史按 UTF-16 字符估算保留数据，超过 32 MiB 时淘汰最早记录，当前记录始终保留。远程图标缓存同时限制为 256 条、估算 8 MiB。以上限制针对本工具持有的资源，不等于整个浏览器堆内存上限；设备内存耗尽导致的浏览器进程退出无法由网页捕获。

图片识别支持直接双击 HTML 的 `file://` 离线模式：按需加载 `ocr/offline-worker.js`，使用内嵌引擎与中英文模型创建 Blob Worker，无需联网或本地服务。HTTP / HTTPS 模式仍使用原有独立资源并检查加载状态。文件缺失、返回错误页或识别库抛出字符串错误时，界面显示具体错误。

Windows 本地使用：可直接双击 `script_tool/剧本工具.html`。也可双击根目录的 `启动剧本工具.cmd`（需 Node.js）使用本地 HTTP 服务；保留命令窗口，关闭窗口会停止服务。服务只监听 `127.0.0.1`，随机选择可用端口。

维护：`scripts/prepare-ocr.mjs` 在构建前从锁定版本的 npm 包复制识别引擎和 WASM，保留许可证，并生成约 10 MB 的 `offline-worker.js`。它包含 Worker、非 SIMD LSTM 引擎和 gzip 模型，在离线模式拒绝访问外部资源。中英文模型为 Tesseract.js 默认的 [tessdata 模型](https://github.com/naptha/tessdata)，以 gzip 形式随站点保存；升级模型时需重新生成离线包并验证识别结果。匹配与离线加载测试为 `scripts/test-image-import.cjs`。



## 手机相册导入与图片分享

在“从图片导入剧本”中选择相册图片，可预览、每次旋转 90 度，或调整四边裁剪比例后开始识别。图片方向按浏览器的 EXIF 解码能力处理，预处理在本机完成，较大图片会缩小以控制内存。支持 PNG/JPEG/WebP；HEIC/HEIF 需要浏览器原生解码支持，不支持时请在相册转换成 JPEG/PNG。单张不超过 20 MB、3200 万像素。

在剧本制图中点击“保存 / 分享图片”，生成 PNG 预览后可长按保存到相册、打开图片，或点击“系统分享”发送到支持的应用。系统文件分享取决于浏览器与系统支持，通常需要 HTTPS；不支持或取消分享时仍可下载 PNG。修改制图设置后需重新生成图片。

## 导入剧本相克和作者规则

支持以 `team: "a jinx"` 或 `team: "a jinxed"` 表示的规则对象。规则不会成为角色，不计入角色数量或夜序。导入后可在“我的剧本”的“剧本相克 / 作者规则”中查看；原始 ID、名称、说明和附加字段随 JSON 导出及草稿保存。

制图时，名称中的两个角色能在当前剧本唯一匹配时，规则显示为角色相克；其他规则显示为特殊规则，避免丢失作者自定义内容。同名角色无法唯一匹配时，不会猜测绑定对象。导入新剧本、载入官方预设、随机生成和清空会替换或清除旧剧本规则。

## 外部工具 JSON 兼容

角色对象支持 `team/type`、`ability/skill/description`；同时出现时优先使用标准字段 `team` 和 `ability`。`traveler` 转换为 `traveller`，`encounter` 转换为 `loric`。未知 ID 仍需完整角色对象，避免猜测同名角色。

导入的 `_meta` 扩展字段（如 `logo`、`version`、`merlinLayout`）和角色附加字段随浏览器草稿与 JSON 导出保留。导出会更新名称、作者、能力、图标、夜序等本站维护的标准字段，因此不保证与原 JSON 逐字一致。清空作者后不会重新带出旧作者。换入新剧本、预设或随机剧本时清除旧元数据。

制图会读取文本形式的 `version` 与 `players` 作为版本及人数初值；其他平台布局字段仅保留，不自动套用。图片中的能力修改仍只影响制图，不改写剧本 JSON。

## 快速制图与手机工作区

生成的剧本图片不展示旅行者，图片角色总数、两侧夜序及相克角色选择也排除旅行者。剧本编辑、JSON 导出及夜序查看器仍保留原有旅行者。只有旅行者的剧本会提示添加其他类型的角色，不生成空图片。

左侧“剧本信息”集中提供标题、剧本作者、支持人数和版本号。作者默认取自当前剧本，人数读取导入元数据中的 `players`；也可自行填写“支持 7–15 人”等文字。图片中的作者和人数使用黑色字体，人数单独显示在标题下方。修改实时更新预览，支持撤销、重做和同一剧本重新打开后保留；仅影响图片，不改写 JSON。留空时不显示对应文字。

标题下方的作者行仅显示“剧本作者：姓名”，不再附加角色数量。

“快速版式”默认选择“复古官方风 · 智能适配（必要时允许自动加长）”。它以暖黄纸张、酒红标题与红色夜序纹理、双栏正文优先生成 1111 × 1500 的海报，默认不添加底部术语说明。角色内容较多时沿用同一双列算法加长；严格固定尺寸可在“图片比例”中选择。原有舒展海报、固定参考比例、阅读版和树叶素材预设继续保留，切换可撤销；切换不会更改剧本角色或规则。

“一键纯净”临时隐藏素材背景、自选背景、底纹与装饰。取消勾选或撤销后恢复原素材，配色与夜序边栏不变。海报和简洁版均显示特殊规则；内容较长时按规则实际高度预留空间，避免覆盖角色。

固定比例正文按两列各自的左边界对齐，缩小时重新换行，保留纸面左右留白和列间距。分类标题及分隔线仍横跨正文区，预览的点击编辑区域与实际角色位置同步。

固定画布的紧凑海报使用按内容计算的排版：完整名称、能力段落及相克／角色规则分别测量换行，每列独立累积高度；按分区实际高度选择连续分列位置，下一分区从较长列的底部开始。正文以原版适配字号为上限，自动换行尽量减少末行 1–2 汉字，保留完整词语；不改变能力文字或显式换段。两列和各分区使用统一角色间距，不为了填满画布拉伸短列或放大正文。先协调间距、行距，确实无法容纳时才小幅缩字。术语框按实际行数预留高度，背景与装饰不参与正文尺寸计算，PNG/SVG 和预览共用同一布局。实现及本轮本地验收见 [正文排版优化](ART_CONTENT_LAYOUT.md)。

手机编辑器提供剧本信息、角色库、我的剧本快捷入口及已选角色数量。制图窗口可切换设置与预览；点击预览中的角色会回到对应编辑项，保存按钮生成 PNG 后定位到保存与分享区域。

桌面制图窗口固定在可视区域内，设置菜单与图片预览分别独立滚动。预览默认适应宽度，以较大字号查看细节；可放大、缩小或切换“查看整图”。缩放工具栏持续可见，图片与点击区域保持一致；只调整屏幕显示比例，不改变 PNG/SVG 的尺寸。手机沿用设置／预览切换，也可缩放图片。真实浏览器回归：`node scripts/test-art-preview-scroll.cjs`（需 Chrome/Chromium），发布产物加 `--release`。

两侧夜序栏的图标最大为 56 个设计像素，随列表长度调整间距，不越出固定画布。可在同一夜晚栏中拖动角色图标插入新位置，首夜与其他夜晚独立；爪牙／恶魔信息标记、黄昏和黎明保留为固定步骤。也支持触控拖动、方向键及点击图标后的上移／下移。调整复用 `ScriptCore.reorderNight`，同步到剧本夜序、浏览器草稿、JSON 和 PNG/SVG；不更改角色能力和角色分区排序。夜序调整单独提供撤回及恢复本夜默认，不混入图片说明与装饰的撤销历史。外部夜序改变后禁用过时撤回，保存失败时保留内存中的可导出顺序并提示备份。`ScriptArt.nightRailBounds` 与 SVG 使用同一几何数据，缩放后点击与拖动仍对齐。回归：`scripts/tests/art-night-drag.test.cjs`、`scripts/test-editor-nights.cjs`。

## 参考图素材海报

“参考图素材 · 浅白树叶（允许自动加长）”继续提供原来的浅白纸纹、树叶角饰、诡雾灰夜序纹理与蓝晶拼字 Logo。该旧预设使用 96 像素图标、28 像素默认能力字和 34 像素角色名，并保留原来的按内容增高行为；需要此行为时须主动选择该预设。原固定参考尺寸、紧凑适配参数、配置来源和历史验证方法见 [复古官方风制图说明](ART_VINTAGE.md)。预设只调整制图，不更改剧本角色、能力或规则，可一次撤销。

角色图标自动叠加对应来源底纹：海外自制使用 `odyssey-watermark.png` 的罗盘纹，奥德赛使用 `山海百绘底纹.png`，群星使用 `象牙塔底纹.png`；暂不使用 `万象星启底纹.png`。正文和两侧夜序均将底纹放在图标背后，官方角色和无法确认来源的角色不添加底纹。导入角色按角色标识、同名同类型的图标或能力匹配角色库来源，避免只凭同名误配。一键纯净会隐藏这些底纹，原始角色和 JSON 数据保持不变。

“标题 Logo 预设”保留十二种原有样式，并新增“古典酒红铭文”。效果由本地 SVG 生成，无需调用 AI 服务；字体随设备可用字体变化。“显示顶部古典徽记”为独立开关；仅“复古官方风”默认显示小型骨饰枝叶，其他预设默认关闭。第三轮仅做绘制微调，固定 1111 × 1500 和双栏结构保持，详见 `ART_VINTAGE_ROUND3.md`。

“上传自己的 / AI 制作的 Logo”支持不超过 8 MB、1600 万像素的 PNG/JPEG/WebP，推荐透明 PNG。Logo 等比放入标题区，内嵌到导出的 PNG/SVG 中，图片只在本机处理。取消“使用上传的 Logo 替代标题”可恢复文字预设；上传、移除和切换均可撤销，重新打开同一剧本的制图窗口会保留 Logo。切换剧本名称后清除旧 Logo；Logo 不写入剧本 JSON，也不随刷新保存。公开静态网站不提供 AI Logo 生成接口；完整源码支持本机服务，密钥由 `OPENAI_API_KEY` 环境变量读取，双击“启动 AI Logo 剧本工具.cmd”后使用它打开的 localhost 地址。真实生成需要有效密钥，不能把密钥放入网页、JSON 或仓库。

“夜序边栏”可选择诡雾灰、凝夜紫、胭脂琉、壁玉白四种真实纹理，也可选无纹理的纸色、深灰或靛蓝边栏。首夜显示在当前剧本存在的爪牙、恶魔信息标记；角色行动顺序仍沿用剧本工具当前设置。月亮、太阳和底部非首夜说明使用本地素材。

特殊规则区使用 `status` 的纸张、纹章、分隔线；空规则不显示该区。“底部术语说明”默认关闭，只有手动选择时才为说明框预留高度。传奇／奇遇合并为“传奇角色 / 奇遇角色”；此分类逻辑不随正文间距改变。复古预设的四角叶子绘制在角色之前，允许靠下角色覆盖叶子，不能让叶子遮住文字或图标；其他预设保留原有绘制顺序。制图图标裁去原图透明留白，网站角色原图不变。素材随 SVG 内嵌，预览、PNG 保存和分享共用同一版式，不依赖远程素材服务。

“一键纯净”也隐藏真实夜序纹理、特殊规则纸张和可选术语说明；夜序信息及规则文字保留，取消勾选即可恢复素材选择。操作界面仍沿用本站原有配色。

维护：24 份精简本地素材位于 `config/script-art/`，来源、原文件摘要、派生文件摘要与合成边线记录于 `script_tool/assets/script-tool/decorations/sources.json`。`npm run prepare:content` 自动运行 `scripts/import_art_decorations.py`，离线校验本地文件并生成 `art-decorations.js`；正常构建不下载原站素材，也不依赖调研目录或 `.sync` 缓存。新增素材需同时更新本地输入及对应摘要。公开素材的署名和权利归原作者，不自动复制参考图中的博物馆标志或作者署名；当前素材未包含参考图的章鱼角饰。


## 屏幕适配与验证

剧本工具按浏览器窗口宽度自动适配，无需手动选择分辨率。宽度达到 2000 CSS 像素时，编辑区使用可用宽度，角色库自动增加卡片列数；“我的剧本”栏最大宽度为 640 像素，避免能力说明过长。普通桌面和手机沿用原有布局，浏览器缩放后按实际窗口宽度重新排版。

运行 `node scripts/test-editor-responsive.cjs` 可用本机 Chromium 检查普通桌面、超宽屏、手机及高像素密度屏幕，验证横向溢出、两栏重叠和角色卡片列数。可用 `CLOCKTOWER_CHROME_PATH` 指定浏览器路径；添加 `--screenshots` 会把验证截图保存到忽略版本控制的 `.sync` 目录。


### 多角色海报智能适配

复古官方风默认使用 `artRatio: adaptive`。优先沿用 1111 × 1500 的原有实测双列算法：同类型角色不跨分区，两列独立计算，先调整间距和行距，再在既有可读下限内适配字号。普通样本与严格固定模式生成相同 SVG。若仍放不下，启用 `overflowLayout.printCompact` 容量配置：收回部分双列沟槽及文字末端留白，保留原字体、行距和图标容器。根据实际文字高度重新选择同类型角色的双列分割位置，角色顺序不变；统一基础角色间距为 14，较短列每个间距最多补偿 4，单角色列不拉伸。分区标题到首角色间距为 20，分区之间保留标题高度和 8 的净间距。上述参数均为 1280 设计坐标。按重新实测的正文底部加页脚预留计算新高度，不切换到旧的自动长图排版。夜序边栏和底部说明按新画布重新定位，宽度仍为 1111。

`artRatio: fixed` 继续严格保持原尺寸，旧存档和主动选择固定尺寸的用户不会被静默切换；溢出提示提供“按原风格自动适配”，支持撤销、重做及制图存档。PNG 沿用既有边长／像素上限保护，超长 SVG 保留实际完整尺寸。验收覆盖正常样本 SVG 不变、31/40/60/100 角色、长能力、特殊规则、传奇／奇遇、术语框与两侧夜序边界。

33 角色作为主要容量验收样本，名单位于 `scripts/fixtures/art-acceptance/reference33.json`（能力取当前角色库，不包含图片作者的私有修改）。`node scripts/render-art-many-roles.cjs --focus33` 生成修改前后实图及附特殊规则／术语框的变体，检查浏览器字形边界、预览与 PNG 导出尺寸、撤销恢复。普通剧本及严格固定模式继续使用原排版，并保持原视觉基线。

复古风附加分区背景：`printDetails.supplemental.background` 控制已有传奇／奇遇分区的暖纸底色。只在当前页存在这两类角色时，从该分区标题横线位置覆盖到纸张底部（不覆盖两侧夜序栏），在底纹、叶子、角色和文字下方绘制；没有附加角色或处于纯净模式时不绘制。标题及角色名称保持原色。`printDetails.patternOpacity` 为已有装饰底纹的透明度，默认 0.30，不增加或替换素材；纯净模式及未选底纹时不绘制。两项均仅影响 SVG 样式，不参与布局测量。

名称和关键词字形：名称显示采用 `ScriptArt Poster Song` 700 实际粗宋体（无额外描边），但 `roleNameMeasureFamily/Weight` 沿用原 SimHei 500 测量，保持既有字号、换行、坐标和分区高度。关键词使用 `ScriptArt Keyword Sans` 500 实际中等字重，取消关键词额外描边；非关键词正文、关键词分类及颜色保持原样。字体同时在浏览器 FontFace、离线字体包及导出 SVG 中指定真实字重，首开制图后缓存。两个新字体合计约 2 MB，关键词字库仅含现有语义词用字；更改关键词集合时应同步补齐字库。名称字库覆盖 GB2312 及打包时全部角色库名称，其他字符沿用原 SimHei 回退。两个新字库均由 Adobe 官方 OFL 字体派生、改名，来源摘要和许可证在字体目录及对应配置中保留。

分区横线只改变路径样式和起点，不改变分区及内容高度：主分区线为深灰棕 1.4，传奇／奇遇线为暖金棕 1.2，透明度均为 0.95；起点为按标题字体实测的文字末端加 14，纵坐标沿用标题基线 -9，端点圆润，右侧有人数信息时继续保留原避让位置。参数位于 `printDetails.heading`，无额外花纹。

分区内留白平衡在全部容量计算完成后执行，不重新计算字号、换行、列宽、分区高度或画布。首角色固定；数量不同的两列，较短列均匀利用 85% 的底部余量；数量相同时，按对应角色名称的位置差选择统一的附加间距，尽量两两对齐。已对齐的列、没有余量的列和单角色列不拉伸。`columnBalance.printCompact` 设置最小余量 6、相对基础间距最多增加 24、已对齐角色允许偏差最多增加 8（均为 1280 设计坐标）。运行 `node scripts/render-art-column-balance.cjs` 可生成风雅集、普通剧本、33 角色及术语框变体的浏览器预览／实际 PNG 导出对比。
